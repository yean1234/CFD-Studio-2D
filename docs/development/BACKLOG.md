## 명시적 제외·보류

- 저장고 누출: 사용자 요청에 따라 제외 · 밀폐 범위 유지
- 해충 이동/생물학적 효과: 현재 격자·UI 구현과 분리 · 크기 기반 연구 요구를 효과 검증으로 확대하지 않음
- 3cm 연구 격자: 자원·셀 예산 확인 전 자동 실행하지 않음
- 반대쪽 `30m` 제안: 단위/의도 미확정 · 30cm로 임의 해석하지 않음
- 이중액침 등 기존 프로젝트·결과: 현재 연구 우선순위와 무관하게 보존
- macOS 지원: 현재 배포 대상 아님

## 기술 위험

| 위험 | 영향 | 대응 기준 |
| --- | --- | --- |
| 고정 셀 전제에서 AMR 도입 | 잘못된 프레임 대응·적분량 | 프레임별 격자 계약과 보존 검사 먼저 |
| 매우 작은 전역 격자 | 메모리/시간/디스크 폭증 | 계획·예산·추정 근거·명시적 선택 |
| 같은 파일의 동시 수정 | Config/결과 덮어쓰기 | revision·소유 범위·스냅샷 |
| 정의만 있는 사용자 속성 | 계산된 것으로 오인 | 지원 어댑터·필드 매핑 검사 |
| 기준 문서와 과거 보고서 혼재 | 완료 상태 오인 | 기준 commit·상태·역사 자료 구분 |
| 에이전트 연결/표시 불일치 | 사용자 모르게 작업 | wait-visible·현재 탭·중단 신호 |
| 로컬 서버 외부 노출 | 인증·파일 접근 위험 | 루프백 유지, 원격화 별도 설계 |

## 항목 종료 기록

- 요구사항 ID, 수정 commit, 검사 명령/환경, 실패 경로, 산출물, 검토자, 남은 제한
