# 인계와 문서 관리

## 변경 단위

- 문제/목표 → 요구사항 ID → 설계 → 코드 → 테스트 → 사용자 안내 → 인계 순서
- 기능 상태는 [추적표](capabilities.json)에 기록 · 근거 없는 완료 선언 금지
- 중요한 변경은 ADR, 미구현 제안은 RFC, 실제 결과는 시험 보고서 사용
- 같은 계약을 여러 문서에 복사하지 않고 기준 문서에 연결

## 책임

| 역할 | 책임 |
| --- | --- |
| 변경 작성자 | 구현·검사·문서·오류·번역·인계 |
| 검토자 | 실제 diff·호환성·실패 경로·증거 검토 |
| 배포 담당 | 배포 범위·데이터 제외·릴리스·롤백 |
| 모델 검토자 | 물리 가정·수치/실험 검증 범위 |

- 실제 담당자는 작업 시작 시 지정 · 이 문서는 특정 인물을 임의 배정하지 않음
- 동일 담당자가 작성/검토를 겸하면 독립 검토 미수행으로 기록

## 갱신 표

| 변경 | 반드시 갱신 |
| --- | --- |
| Config 키·자료형 | 데이터 계약·오류·스키마·왕복 검사·에이전트 JSON 안내 |
| 실행기·솔버 | 요구사항·지원 표·종료/복구·실행 테스트 |
| 격자 | 형상·대칭·지역 우선순위·셀 예산·수렴 기준 |
| 결과 | 단위·배열·시간 축·Viewer·CSV·원본 추적 |
| 화면 | 사용법·도움말·번역·실제 화면 검사 |
| 파일/모듈 이동 | 구조·import·자원 경로·소스 목록 |
| 새 오류 | JSON 사전·UI 번역·원인/해결·실패 검사 |
| 문서 업데이트 요청 | AGENTS.md의 전체 문서 범위 |

## 문서 목록과 자동 검사

```bash
python tools/check_development_docs.py --write-inventory
python tools/check_development_docs.py
```

- 목록 생성은 Git 추적 파일과 스테이징 파일 기준 · 사용자 미추적 연구 파일은 수집하지 않음
- 일반 검사는 링크·필수 문서·요구사항 ID·코드/테스트 경로·목록 최신 여부 확인
- 내용 정확성, 실제 버튼 동작, CFD 타당성은 사람이 검토하고 별도 검사
- 일반 검사에 네트워크·앱 실행·솔버 실행·사용자 데이터 수정 없음

## 이력 관리

- 날짜가 붙은 검토 기록은 역사 자료로 유지 · 현재 사실은 기준 문서에 작성
- 새 설계가 과거 ADR을 바꾸면 기존 파일 삭제 대신 대체 ADR 링크
- baseline commit은 문서가 대조한 코드 기준 · 이후 기능 변경 시 재검토 날짜와 근거 갱신
- 미완료 항목은 구현/검사 증거가 충족될 때만 닫음
- 문서에 개인 실험 조건·민감 데이터는 넣지 않고 별도 비공개 산출물 참조

- 목적·범위·기준 commit·미커밋 변경

- 수행한 명령·테스트 결과·실제 산출물 위치
- 실행 중 프로세스·대기열·미저장 UI·현재 에이전트 상태
- 막힌 이유·미확정값·다음 명령·중단 조건
- 실험 검증/수치 검증/프로그램 동작 검사의 구분
