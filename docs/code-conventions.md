# 개발 규칙

## 보존과 책임

- 기존 프로젝트 입력과 Raw를 수정하지 않는다. 변경은 새 설정·입력 버전·실행 시도로 남긴다.
- Studio HTTP/프로젝트/Viewer를 재사용한다. 물리 모델 연결은 명시적 어댑터로 분리한다.
- 실행 완료와 품질 검사 통과를 구분한다. 미지원 기능을 다른 모델로 대체하지 않는다.
- 시각화 보간·표시용 데이터는 원본 수치장을 변경하지 않는다.

## 코드

- Python은 4칸 들여쓰기, 모듈·함수는 snake_case, 클래스는 PascalCase, 상수는 UPPER_CASE.
- 코드 식별자는 영어, 신규 주석·사용자 오류 문구는 한국어를 기본으로 한다. 외부 소스와 표준 용어는 원문을 유지한다.
- 주석은 보존량, 좌표·단위, 가정, 예외 처리 이유를 설명한다. 자명한 대입문 설명은 추가하지 않는다.
- 값·단위·근거를 함께 저장한다. 임의의 문헌값이나 탐색 범위를 기본값으로 만들지 않는다.
- JSON은 구조화된 파서로 처리한다. 해시는 키 정렬·UTF-8·NaN 금지 직렬화를 사용한다.
- 저장 경로는 Path, 셸 인수는 목록 또는 shlex.quote를 사용한다. 사용자 경로를 셸 코드에 직접 삽입하지 않는다.
- UI 사용자 문자열은 textContent로 표시한다. 자동 갱신은 편집 중인 폼을 덮어쓰지 않는다.
- 기존 대형 파일의 무관한 재포맷은 하지 않는다. 현재 일부 레거시·초기 UI는 이 규칙으로 일괄 정리하지 않았다.

## 검사·배포

- 새 동작에 정상·경계·실패·재시도 테스트를 추가한다. 실제 솔버 검증은 운영 프로젝트와 분리한다.
- 재현 패키지의 코드 실행은 사용자의 명시적 명령에서만 허용한다.
- 커밋 전 `git diff --check`, 테스트, 스테이징 목록을 확인한다.
- 개인 설정, 인증 정보, 연구 원문, 협력 자료, SQLite, Raw, 시각화 산출물은 Git에 넣지 않는다.
- 제3자 코드의 버전·라이선스를 기록한다. 자체 코드의 라이선스를 임의로 변경하지 않는다.
