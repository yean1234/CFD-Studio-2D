# 개발 규칙

## 적용 범위

- Studio 자체 Python·JavaScript·CSS·JSON과 테스트에 적용
- 기존 파일은 수정한 범위부터 적용 · 무관한 전체 재포맷이나 공개 키 변경 금지
- 외부 라이브러리·생성 파일·연구 원문은 원본 유지
- 기존 프로젝트·Raw·결과·미커밋 변경 보존

## 구성과 책임

| 구분 | 책임 |
| --- | --- |
| UI | 입력·상태·결과 표시, 사용자 조작 전달 |
| Config 계약 | JSON 구조·자료형·필수값·단위·표시 양식 검사 |
| Template | 솔버·입력 양식·초기 형상 정의 |
| 실행 어댑터 | 지원하는 Config를 솔버 입력과 실행 명령에 연결 |
| 저장 | 프로젝트·Case·실행 스냅샷·원본 결과 관리 |
| Viewer | 저장된 결과를 읽어 표시·조회·내보내기 |
| 에이전트 | 같은 UI를 조작하고 진행 상태·오류·인계 제공 |

- 프로젝트 이름으로 입력 양식이나 시각화 동작 분기 금지
- 솔버별 차이는 명시적 기능 정의와 어댑터에 배치
- 솔버 설치·실행 연결·계산 완료·수치 검사·실험 검증을 각각 구분
- 미지원 기능은 이유를 표시하고 다른 모델로 자동 대체하지 않음

## 이름과 형식

| 대상 | 규칙 | 예시 |
| --- | --- | --- |
| Python 모듈·함수·변수 | `snake_case` | `project_storage`, `read_frame` |
| JavaScript 함수·변수 | `camelCase` | `reviewStatus`, `frameIndex` |
| 클래스 | `PascalCase` | `ProjectStorage` |
| 고정 상수 | `UPPER_SNAKE_CASE` | `MAX_FRAME_COUNT` |
| CSS 클래스 | 기존 모듈 접두사와 하이픈 | `fc-review`, `ew-case-fill` |
| JSON 키·오류 코드 | 기존 공개 계약 보존 | `time_s`, `CFG-J004` |

- 식별자는 영어 · 분야 표준 기호와 외부 API 이름 유지
- 의미가 불분명한 약어 대신 역할이 드러나는 이름 사용
- 좌표 루프의 `x`, `y`, `z`, 인덱스의 `i`, 표준 물리량 `U`, `T` 등은 허용
- Python 들여쓰기 4칸 · 새 JavaScript 블록 2칸 · 탭과 공백 혼용 금지
- 새 코드는 한 줄에 한 처리 · 복잡한 조건·예외 처리를 한 줄에 압축하지 않음
- 인접 코드의 따옴표·세미콜론 스타일 유지 · JavaScript 신규 모듈은 세미콜론 사용
- 파일 인코딩 UTF-8 · 플랫폼 실행 스크립트의 줄바꿈·인코딩 요구사항 유지
- 현재 압축된 초기 UI 코드 전체에 이 형식이 적용된 것은 아님

## 함수와 상태

- 한 함수는 하나의 책임 · 검증·변환·저장·표시를 가능한 한 분리
- 읽기 함수에서 파일 생성·자동 복구·실행 시작을 숨기지 않음
- 입력값을 변경하는 함수는 변경 대상과 시점을 이름 또는 주석에 명시
- 시작한 Case의 Config는 스냅샷으로 고정 · 재설정은 새 Case 또는 새 실행 시도
- 비동기 응답은 요청 당시 프로젝트·Case·프레임과 대조한 뒤 반영
- 잠금은 획득한 요청만 해제 · 이벤트·타이머·3D 리소스는 화면 종료 시 정리
- 화면 명령 전달과 저장·계산 완료를 별도 판정

## Config와 물리량

- Template에서 출력한 JSON과 스키마를 기준으로 값과 입력 화면 구성
- JSON 키·표시 이름·입력값을 구분 · 사용자 이름과 원본값 번역 금지
- 스키마 버전·식별자·단위·사용자 속성 메타데이터 보존
- 외부 JSON은 파싱 후 구조·자료형·범위·크기를 검증 · `eval` 금지
- 알 수 없는 값은 누락·미지원 상태로 표현 · 오류나 누락을 0으로 치환 금지
- 값·단위·출처·가정을 구분 · 문헌값을 근거 없이 기본값으로 확정 금지
- 좌표계·원점·축 순서와 단위 변환은 변환 경계에서 명시
- 시간간격·저장 간격·반복 횟수·재생 배속을 구분
- 표시용 보간·샘플링은 원본 수치장과 계산 격자를 변경하지 않음

## 저장과 실행

- 저장 경로는 `Path` 등 경로 API로 구성 · C 드라이브 또는 설치 위치 고정 금지
- 새 저장은 임시 파일과 검증을 거쳐 공개 · 실패 시 기존 연결과 원본 보존
- 해시용 JSON은 정렬된 키·UTF-8·NaN 금지 직렬화
- 셸 인수는 목록으로 전달 · 셸이 필요한 경계에서만 해당 셸의 인용 규칙 적용
- 사용자 경로를 명령 코드에 직접 삽입 금지
- Windows와 WSL 경로 변환은 명시적인 경계 함수에서 수행
- 재시도·재개·새 계산 구분 · 완료한 계산을 자동 재실행하지 않음

## UI와 오류

- 화면 구조와 조작 방식은 프로젝트마다 동일하게 유지
- 사용자 입력 문자열은 `textContent`로 표시 · HTML 삽입 시 별도 이스케이프
- 자동 갱신이 편집 중 값·선택·스크롤을 덮어쓰지 않도록 구성
- 기본 필드의 이름·자료형과 사용자가 추가한 속성의 편집 권한 구분
- 사용자 문구는 한국어·영어·일본어 번역 경로에 등록
- 오류는 안정적인 코드·발생 위치·원인·다음 행동 제공
- 예외를 무조건 무시하지 않음 · 허용된 정리 실패나 선택적 기능 실패는 이유 명시
- 오류 로그에 인증 정보·전체 Config·대용량 원본장을 무조건 포함하지 않음
- 에이전트 일시정지·조작 담당·사용자 입력 충돌을 존중 · 화면 검토와 실행 권한 구분

## 주석

- 자체 코드의 신규·수정 주석은 간결한 영어로 작성 · 사용자 문구는 번역 체계 사용
- 기존 한국어 주석은 해당 영역 수정 시 같은 기준으로 정리 · 외부 출처·라이선스 유지
- 모듈 시작: 역할을 한두 줄로 설명
- 함수 문서: 호출자가 알아야 할 입력·반환·단위·부작용·실패 조건 중 필요한 내용만 명시
- 처리 주석: 코드만으로 알기 어려운 이유·순서·호환 조건·제약 설명
- 한 주석에 한 가지 내용 · 짧은 문구는 마침표 생략
- 대입·반복을 그대로 읽는 주석, 대화체, 개인 작업 기록, 과거 오류 회고 제거
- 구체적 설명 없이 `임시`, `주의`, `TODO`만 남기지 않음 · 남길 경우 조건과 추적할 이슈 명시
- 복잡한 코드는 먼저 책임을 나눌 수 있는지 검토 · 긴 주석으로 구조 문제를 가리지 않음
- 주석 변경 시 실제 구현과 대조 · 보장하지 않는 동작을 설명하지 않음

## 검사와 배포

- 동작 변경은 관련 정상·경계·실패 경로 검사 · 구현을 그대로 반복하는 테스트 지양
- 주석만 변경한 경우 실행 토큰·구문 구조 비교와 문법 검사로 동작 변경 여부 확인
- Python docstring은 `__doc__`에도 반영되므로 도움말·내성 검사 영향 구분
- UI 조작이 바뀌면 실제 화면 검증 · CFD를 실행하지 않았으면 실행했다고 보고하지 않음
- 커밋 전 diff·관련 검사·스테이징 목록 확인
- 개인 설정·인증 정보·프로젝트 데이터·Raw·캐시·연구 원문은 업로드에서 제외
- 제3자 버전·라이선스 유지 · 라이선스 임의 변경 금지
- “문서 업데이트” 범위는 저장소 [AGENTS.md](../AGENTS.md) 기준
