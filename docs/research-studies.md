# 연구 실험 사용법

## 두 작업 경로

| 주소 | 목적 | 실제 계산 |
|---|---|---|
| `/studies` | 정규화 추적자 검증 예제의 후보 생성·순차 실행·비교 | OpenFOAM `porousTracerFoam` |
| `/studies/design` | 저장고 연구 변수·형상 후보·제약 검토 | 아직 미연결; 예약 차단 |

두 화면 모두 기존 Studio 서버 안에서 동작한다. 기존 액침냉각·저장고 프로젝트는 보존한다. 검증 결과의 `3D 보기`는 기존 Viewer를 연다. 연구용 형상 미리보기는 결과 농도장이 아니다.

## 검증 예제

1. Studio를 실행하고 `/studies`에서 실험을 만든다.
2. 확산 계수 또는 공극률 한 변수를 선택한다. 수동 목록, 일정 간격, 1차원 LHS 중 선택한다.
3. 후보 확인에서 중복·범위 제외 이유를 확인하고 실행용 버전을 확정한다.
4. 확정 후보 실행 예약을 누른다. 실행 ID별 로그·물리시간·실제 소요시간·수치 검사 결과를 확인한다.
5. `3D 보기`에서 C/C_ref를 재생한다. 비교 그래프는 공간 평균이며 동일 시간 구간·단위의 통과 결과만 포함한다.
6. 대표 사례 패키지를 만들고 ZIP을 내려받는다. 가져오기는 해시 검사와 새 폴더 추출만 수행한다.

기본 예제는 1×0.2×0.2 m, 1,280셀, U=0, 0~1 s, 계산 간격 0.005 s, 출력 0.1 s이다. 최초 시각 0을 포함해 11프레임이다. 예제 계수와 허용 범위는 **수치 시험용 가정**이지 쌀·ClO₂ 물성이 아니다. 질량 보존 때문에 평균 농도가 거의 일정해도 국소 분포는 변할 수 있다. 균일한 평균값을 방제 효과로 해석하지 않는다.

실행 환경에는 OpenFOAM v2312, Python+NumPy, `porousTracerFoam`이 필요하다. 기존 설치 배치가 이 추가 솔버까지 자동 설치하는 것은 아니다. WSL에서 다음을 실행한다.

```bash
source /usr/lib/openfoam/openfoam2312/etc/bashrc
cd tracer_transport/solver
wmake
```

저장소 루트로 돌아와 새 결과 폴더를 지정하면 UI 없이 전체 인수 시험도 가능하다.

```bash
python3 -m study_platform.smoke output/study_my_acceptance
```

## 연구 변수와 후보

- 설계변수: 배치, 간격, 공급 위치, 총 공급량.
- 환경·물성: 온도, 누설, 포대 저항, 공극률, 확산·반응 계수.
- 수치: 격자, 계산 시간간격, 평가시간, 저장 간격, 수렴 기준.

물성·범위는 빈 값에서 시작한다. 공통 조건 JSON과 각 변수 값을 입력하거나 이전 설계 JSON을 가져온다. 총 공급량은 `{ "value": ..., "unit": "...", "evidence": "..." }`로 지정한다. 운전량을 추천하지 않는다.

초기 공동 비교에서는 환경·물성·수치·총 공급량을 고정하고 배치·간격·공급 위치만 탐색한다. 일반화된 모든 변수의 탐색·자동 계산은 아직 제공하지 않으며 화면에서도 선택을 제한한다. 미정 환경값 `null`은 설계 초안에 보관 가능하지만 실행 가능하다는 의미가 아니다.

배치는 `blocks` 배열이며 각 블록에 `id`, `min:[x,y,z]`, `max:[x,y,z]`, `mass_kg`가 필요하다. 원점은 저장동 바닥 모서리, z는 높이, 길이는 m이다. 질량은 사용자가 지정하며 밀도에서 임의 환산하지 않는다. 공급 위치는 `[[x,y,z], ...]`이다.

`common`에는 다음이 필요하다.

| 필드 | 의미 |
|---|---|
| geometry | length_m, width_m, eaves_m |
| stored_mass_kg, mass_tolerance_kg | 공통 저장량과 사용자가 정한 허용오차 |
| source_count, supply_duration_s | 고정 공급원 수·공급시간 |
| wall_clearance_m, maximum_stack_height_m | 벽 이격·적재 높이 한계 |
| aisles | min/max, width_axis(0 또는 1), minimum_width_m |
| allowed_source_regions | min/max로 지정한 공급 허용 영역 |

`spacing_m` 고정값은 최소 블록 이격 조건이다. 자동 계산은 입력 배치의 최소 수평 축별 간격을 산출한다. 간격 탐색은 `layout.spacing_axis`가 지정된 **단일 열 배열**만 지원하며, 첫 블록을 고정하고 나머지 블록을 0(x) 또는 1(y)축 순서로 옮긴다. 블록 크기·질량은 유지한다. 복잡한 여러 열 배치는 완성된 배치 후보 목록으로 입력한다. 범위 탐색 형식은 `{ "bounds": [최소, 최대], "count": 후보수 }`이다.

현재 입력을 기준안으로 지정하고 후보 생성·검사를 누른다. 후보 행을 선택하면 3D와 기준안 대비 변경값을 확인한다. 저장량·충돌·벽/블록 간격·통로·공급원 수/중복/허용 영역을 검사하고 제외 이유를 남긴다. 임의로 유효 위치로 보정하지 않는다. 실제 공급 시간함수는 아직 미정이며, 총량/공급시간으로 계산한 **평균** 공급률을 일정한 순간 공급률로 취급하지 않는다. 가스 공급을 공기 유량으로 치환하지 않는다.

후보는 최대 128조합+기준안으로 제한한다. 시드를 기록하되 명시적 목록 조합은 난수를 사용하지 않는다. 버전 확정은 형상·입력·검사·소스 스냅샷을 저장할 뿐 실제 저장고 CFD를 돌리지 않는다. 새 버전 확정 후 이전 버전과 시도는 삭제하지 않는다.

## 보존·실패 처리

- `cfd_studio/Studies`에 SQLite, revisions, attempts, packages, imports를 보관한다. Git 제외 대상이다.
- 실행 입력과 소스 해시를 검사하고 변경되었으면 실행하지 않는다. 요청 ID 중복은 중복 실행으로 이어지지 않는다.
- 대기열 보류는 현재 계산을 죽이지 않고 다음 계산부터 대기한다. 후보 오류와 환경 오류를 구분하고 환경 오류에서는 대기열을 보류한다.
- 앱 연결을 잃은 실행은 `복구 확인 필요`로 남긴다. 살아 있는 솔버를 중복 실행하지 않는다. 이 상태를 자동 복구하는 UI는 아직 없다.
- 백엔드 재시도는 새 attempt를 만들고 원본을 보존한다. 체크포인트 재개는 동일 후보·새 폴더에서만 가능하다. 재시도·재개 버튼은 아직 UI에 없다.
- 기존 프로젝트의 실행·중단·재개 기능은 이 대기열과 별도이다. 현재 여러 큐/기존 솔버 사이의 PC 전체 자원 할당은 통합하지 않았다.

## 재현 패키지

대표 예제 패키지에는 실제 입력, 소스 스냅샷·Git HEAD, 환경·솔버 바이너리 해시, Raw, 수치 검사, Viewer 데이터, 비교 도표와 허용오차가 들어간다. 연구 PDF와 협력 원자료는 포함하지 않는다. ZIP 가져오기는 경로 이탈·링크·Windows 예약 경로·중복·해시 변조를 거부한다. GUI 업로드 한도는 20 MiB, 내부 검사는 펼친 데이터 256 MiB·12,000항목이다.

패키지 소스를 검토한 뒤 `code/` 안에서 명시적으로 재현한다. 새 환경에서는 `FOAM_USER_APPBIN`을 별도 디렉터리로 지정해 솔버를 빌드하고 PATH에 추가한다. 가져오기 자체는 설치·컴파일·실행을 하지 않는다.

```bash
python3 -m study_platform.reproduce /path/to/imported /path/to/new_result
python3 -m study_platform.reproduce /path/to/imported /path/to/new_figures --figures-only
```

후처리 조회는 `study_platform.fields.FieldProvider`를 사용한다. 위치·물리시간을 받아 저장된 농도를 조회하며, 없는 온도장·범위 밖 시간은 유효하지 않은 결과로 반환한다. 곤충 행동 계산은 포함하지 않는다.
