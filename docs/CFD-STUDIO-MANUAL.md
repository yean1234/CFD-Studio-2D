## 설치 환경

- **지원 운영체제: Windows 10/11 x64**
- **macOS(Mac) 미지원** · 현재 배포판은 Windows 실행 환경과 WSL2를 사용

- [필수 프로그램·설치 BAT·설치 순서](../cfd_studio/README.md)
- `설치.bat`: 최초 계산 환경 준비. WSL 자체·전용 솔버·GPU 환경 설치와 구분
- `실행.bat`: 일반 실행
- Windows Python 포함. Linux OpenFOAM·NumPy는 계산 환경에 필요
- 기존 프로젝트·계산 폴더를 삭제해서 재설치하지 않음

## 프로젝트와 실행

- CFD Template: 솔버·Config 양식·초기 형상 정의
- 프리셋: 각 Template에 속한 값 묶음
- 프로젝트 찾기: 기존 프로젝트 폴더의 형식·실행 목록 검증 후 등록
- 프로젝트: 이름·설명·CFD Template·기본 프리셋 참조·생성 시 입력값 사본·실행 목록 보관
- 기본 프리셋 변경: 이후 생성하는 실행에만 적용
- + CFD Case: 개별 설정·목표·종료 조건을 초안으로 저장
- 실행 시작: 입력 JSON과 SHA-256 고정, 다른 실행·프리셋에 소급 적용하지 않음
- 대기열: 순서·제외·다음 실행부터 일시정지, 실패 시 자동 정지
- 재시도: 별도 시도 폴더, 완료 계산 자동 재실행 차단
- 수렴 종료: 연속 유지 구간 판정 미연결로 선택 비활성
- 프레임 종료: 초기 프레임 포함 여부와 완전 저장 개수 확인
- Config 보기: 계산 중·완료 후 실행에 사용한 입력 조회, 기존 입력 수정 차단
- Template별 입력값 프리셋: Studio 등록부의 `form_presets`에 보관
- 프로젝트 Config: 프로젝트 생성 시 사본 저장, 새 Case의 시작값으로 사용
- 설정 가져오기·내보내기: JSON 파일 사용
- 출처·근거: 설정 목록 마지막 **출처** 항목에 표시, 원본 입력 유지
- 공통 Viewer: 이중액침·저장고·정규화 결과에서 동일한 캔버스·재생·레이어·Export 사용
- 화면 구성은 공통이며 표시 데이터는 계산 모델에 따라 구분
- 실행 전환 상태: 현재 탭에서 실행별 시간·물리량·시점 유지
- 실행별 보관: 입력 사본·입력 SHA-256·솔버 로그·계산 원본·조회용 배열
- 재실행: 새 실행과 새 결과 폴더 생성, 앞선 결과 보존
- 실행 완료: 지정 시간까지 계산·출력 검사 통과
- 수치 수렴·실험 검증: 실행 완료와 별도 표시
- 외부 연결 목록: `cfd_studio/_runtime/executions/external_results.json`
- 저장 위치: 프로젝트 생성·설정에서 지정한 폴더
- 백업: 프로젝트 폴더 전체와 이전 형식의 외부 연결 원본 보존
- 계산 환경: WSL OpenFOAM·Linux NumPy 필요
- 앱 재시작: 실행 기록·대기열 복원, 다음 실행은 일시정지
- 실행 중 계산: 완료 기록을 추적, 시작한 시도 자동 재실행 차단
- 기록 파일: `queue.json`, 시도별 `input.json`, `job.json`, 로그
- 액침냉각: 적용된 입력을 `applied_input.json`에도 보관

## 저장 구조

| 위치 | 내용 |
|---|---|
| `project.cfdproj` | 프로젝트 이름·설명·Template·기본 프리셋 참조·초기 Config·실행 연결 |
| `ProjectSettings/executions.json` | Case 설정·목표·종료 조건·대기열 기록 |
| `Cases/<Case>/Attempts/<시도>/input.json` | 실행 시 고정된 설정 스냅샷 |
| 같은 시도 폴더의 `job.json`, 로그 | 실행 상태·입력 해시·로그 |
| 같은 시도 폴더의 `Raw` | 저장고 계산 원본·조회 배열 |
| 같은 시도 폴더의 `Results/<실행>` | 이중액침 등의 Viewer 결과·설정·Raw_Data·변환 캐시 |
| `Results` | 기존 결과를 프로젝트로 복사할 때의 보관 위치 |
| `Cache` | 프로젝트 캐시 영역 |

- Studio 공통 목록: 프로젝트 경로와 전체 대기열 순서 참조
- 설정 프리셋: Studio에서 독립 관리. 실행 입력은 프로젝트 안에 별도 보관
- Windows 드라이브: 지정 경로 유지. WSL 실행 시 드라이브 경로 변환
- 이중액침 계산 작업 공간: WSL 공통 작업 폴더 사용. 완료 시 프로젝트에 원본 복사·검증 후 다음 Case 진행
- 저장고: 프로젝트 내부의 독립 실행 폴더에서 계산
- 기존 형식: 원본 이동 없이 연결 유지. 위치 변경 시 복사 후 파일 해시 검사
- 경로 변경 실패: 기존 프로젝트 연결 유지, 부분 복사본은 새 위치에 남을 수 있음
- Studio 재시작: 등록된 프로젝트 실행 기록과 대기열 복원
- 원본 데이터는 프로젝트별 지정 폴더에 저장. 이전 형식의 경로 값은 해당 결과 조회에 사용

## Viewer 모드

- **3D Virtual** 버튼: 선택한 Case의 3D 결과·재생
- **Data Sheet** 버튼: 선택한 Case의 두 그래프 조회
- 각 그래프: 결과 항목·읽기 상태·조회 위치·PNG·CSV 내보내기 독립 관리
- 3D Virtual Export: 영상·3D 화면 PNG
- Data Sheet Export: 현재 그래프 PNG·읽어온 구간의 CSV
- 활성 모드: 버튼의 파란 테두리·배경과 선택 상태로 표시
- Case 이름: 3D와 그래프에 적용할 실행 하나 선택
- CFD Case 제목 오른쪽 **다시 읽기**: 선택한 실행 결과 갱신
- 그래프: 읽은 구간의 저장값 표시, 클릭 위치에서 가장 가까운 저장 X 선택
- 값 표시: 선택한 Case의 저장 시점에서 조회, 그래프 수치는 보간하지 않음
- 선 연결: 저장점 사이의 시각적 연결, 중간값을 새 계산값으로 제공하지 않음
- 비정상 해석 X축: 물리시간 s
- `simpleFoam` 정상 해석 X축: 솔버 반복 횟수
- 읽기 단위: 최대 16개 저장 시점
- 항목별 저장 시점 200개 이하: 자동으로 전체 읽기
- 200개 초과: 일부 구간부터 표시, **전체 구간 읽기**로 계속 조회
- 읽는 중 **읽기 중지**, 모두 읽은 후 **다시 읽기** 표시
- Data Sheet Viewer는 그래프에서 시점을 선택. Config와 원본 검증 기록은 별도 보존
- 왼쪽 **전체 평균**: 윗줄에서 선·막대·산점도 선택, 아랫줄에서 최대 3개 물리량 선택
- 단위별 Y축 사용, CSV는 각 항목의 원래 단위·값 보존
- 두 그래프 배경 패널의 높이·그래프와 상세값 위치 정렬
- 내부 그래프 폭은 패널의 80%, 아래 상세값과 여백 유지
- 평균 기준: 저장된 전체 유효 셀의 산술 평균. 체적 가중 평균이 아님
- 오른쪽 **좌표 조회**: X·Y·Z(m) 입력 후 **조회**. 각 저장 시점의 최근접 저장 셀 값 표시
- 좌표 영역: 저장고는 저장동 형상, 그 외 결과는 선택한 물리량의 저장 격자 범위
- 입력란에 최소·최대 표시, 범위 밖 입력은 확정·조회 불가. 저장고 Z 상한은 Y에 따른 지붕 높이 반영
- 빈 셀·손상 프레임은 빈값으로 표시. 영역 밖 좌표는 오류 표시
- 좌표 그래프의 PNG·CSV에는 입력 좌표와 조회 방법을 함께 기록
- 원본 폴더: **CFD → 결과 폴더**

| 단상 저장고 | 유속·속도 성분·압력·난류 운동에너지·소산율 |
| 정규화 추적자 | 농도·흡착량 |

- 전체 평균 그래프: 저장된 유효 셀의 평균값 사용
- 전체 CSV: 저장 결과가 제공하는 평균·최솟값·최댓값 등의 통계 포함
- 저장고: 원본장과 배열을 대조한 전체 저장 셀의 산술 통계
- 기존 이중액침·단상 결과: 저장 시각화 격자의 통계, 체적 가중 평균 아님
- 기존 온도 빈 셀 제외, 상분율 점유 마스크 적용, 구형 유속·압력·난류의 빈 평면 처리는 3D와 동일
- 압력: Case에 밀도가 저장된 경우 Pa, 그렇지 않으면 원래 단위 m²/s²
- T5: Case에 저장된 입구 온도 입력값
- T6: Case의 코일 이력·유량·전열계수에서 기존 식으로 계산한 값, 직접 측정값 아님
- 열전대: 저장된 이력 전체 조회 지원
- 없는 필드는 그래프 메뉴에 생성하지 않음
- 사용자 정의 Template: 지원 엔진의 출력 목록을 따름, 새로운 솔버의 임의 출력 형식은 별도 연결 필요
- 수치 검증·실험 검증 완료 여부는 그래프 표시 성공과 별개

## CFD Template

- **여기에 없음**: 해당 조건을 지원하는 등록 솔버·양식이 없음을 표시 · 지원하지 않는 항목 안내 후 추천·생성 중지 · 선택 수정 또는 취소 가능
- 생성 순서: 해석 조건 설문 → 솔버 추천·선택 → 빈 Config 양식 생성 → 이름·설명 입력 및 저장
- 추천 조건: 유체·해석 목적·정상/비정상·유동 모델·영역·격자 준비·종료 방식
- 등록된 솔버 양식에서 모든 답변을 지원하는 후보만 제시 · 계산 속도나 정확도 순위는 아님
- 일치하는 후보가 없으면 생성 불가 · 서버에서도 선택 조건 재검사
- 기존 Template 재편집은 솔버 유지 · 설문 취소 시 기존 양식 유지

- Template: 솔버·해석 조건·항목·자료형·단위·초기 형상 정의
- 입력값은 프로젝트 생성 시 작성하거나 Template별 프리셋에서 불러오기
- 이름 아래에 설명 배치 · 솔버 설명에 원작자·소스 링크 제공
- 기존 Config Template 선택 항목 제거
- 기존 연결 Template의 입력값은 별도 프리셋으로 유지
- 기존 프로젝트·Case·결과와 내부 ID 유지
- 신규 Template: 프로젝트·Config·프리셋 저장 가능 · 계산은 실행기 연결 필요

## 표시 밀도

- 위치: 3D Virtual 오른쪽 결과 패널 맨 위
- 적용: 이중액침·저장고·단상 유동의 속도 벡터
- 프로젝트를 전환해도 선택한 표시 밀도 유지
- 기본 표시 밀도: 세밀
- 벡터 상한: 표준 1,500개, 세밀 6,000개, 매우 세밀 18,000개
- 저장고: 공간 구역별 실제 저장 셀 중심에서 표본 추출
- 이중액침·단상 유동: 저장 시각화 격자에서 공간 간격에 따라 표본 추출
- 저장고 단면: 단면에 해당하는 셀을 먼저 고른 후 밀도 적용
- 벡터 표시: 각 결과의 기존 유속 표시 기준 유지
- 화살표 길이: 유속을 시각적으로 표현한 길이, 입자의 실제 이동 거리 아님
- 저장고 읽기 상한: 프레임당 125,000셀, 상단에서 표시 / 전체 셀 확인
- 저장고 메모리 사용: 프레임 크기에 따라 최근 2~8프레임 유지
- 저장된 계산값·계산 격자 변경 없음, 공간 사이의 새 CFD 값 생성 없음
- 표시 밀도 증가와 계산 격자 세분화는 별개

## 공간 정보

- 초기 형상은 Template에서 프로젝트로 복사 · 프로젝트 내 형상 수정·추가·삭제 가능
- 초기 형상 수정은 기존 프로젝트·프리셋·Case 스냅샷에 소급 적용하지 않음
- 요소별 `name`은 표시 이름 · 내부 선택은 원본 항목 경로로 구분
- `role`은 요소 분류 · `config_bindings`는 Config 항목 경로 배열
- 네임태그와 왼쪽 목록 선택 동기화 · 선택 요소 강조 · 치수 변경 시 3D 갱신
- 연결된 물성·발열량은 기존 Config 항목의 원본 값 편집 · 같은 항목을 참조하면 값 공유
- 역할·연결 정보만으로 격자 경계나 솔버 사전을 자동 생성하지 않음
- 전기 해석 등 새로운 물리 모델은 해당 솔버의 입력·실행 연결 필요
- 기존 이중액침의 발열면 `heater.cpus` 표시 · 총 발열량 `heater.total_W` 연결

- Config·Template·Case의 가운데에 3D 형상 상시 표시 · 항목별 **JSON** 버튼으로 오른쪽 편집창 표시
- 기본 형상 분류: **공간 형상** · 선택한 Template의 실제 형상 항목 표시 · 다른 솔버에 저장고 형상을 자동 추가하지 않음
- 코드 입력과 3D 미리보기 제공
- JSON 데이터만 해석 · Python·JavaScript 코드는 실행하지 않음
- 지원 단위: `m`, `cm`, `mm` · 미리보기 좌표는 m로 환산
- `geometry.regions`, `geometry.fluid_regions`, `geometry.solid_regions`: 형상 배열 또는 이름별 객체
- `box`: `shape`, `unit`, `min`, `max`
- `sphere`: `shape`, `unit`, `center`, `radius`
- `cylinder`: `shape`, `unit`, `center`, `radius`, `height`, `axis`
- 좌표 배열: `[x, y, z]` · 원기둥 중심은 높이의 중간 지점 · axis는 `x`·`y`·`z`
- 기존 Config: `tank`·`board`·`coil`의 mm 좌표, `geometry_spec.geometry`의 박공지붕 외형, `loading.blocks`의 m 좌표 지원
- 표시 제외: 외부 CAD·STL·격자 파일, 상세 사일로 형상, 상분율·측정 지점
- 미지원 형식·미입력 치수는 안내에 표시 · 형상을 임의로 추정하지 않음
- 미리보기는 형상 확인 기능 · 유효 격자 생성, 경계조건 연결, 솔버 실행 가능성을 판정하지 않음
- 신규 공간 JSON을 기존 솔버가 자동 해석하지 않음 · 실제 계산에는 해당 Config 형식의 실행 연결 필요
- 미리보기 최대 1,000개 형상 · JSON 최대 1 MB
- Template의 항목별 JSON은 해당 필드 정의 · 초기 형상은 정의의 `value`에 보관 · 전체 Template JSON은 `version`·`fields` 양식 정의
- Config의 공간 코드는 실제 공간 항목 값 · 다른 물성·계산 항목은 보존
- **JSON 저장**은 편집기의 초안에만 반영 · 최종 저장 전 프로젝트·프리셋·실행 스냅샷은 변경하지 않음

### 전체 공간 형상 JSON

- 3D 형상 블록의 **JSON** 버튼으로 전체 공간 정의 조회·수정
- `format: "cfd-spatial-config"`, `version: 1`, `sections` 구조 사용
- `sections.geometry`: 공간·영역·요소의 전체 정의 · 이름·좌표·단위·물리 설정 연결 포함
- `sections.mesh`: 격자 설정 · 기존 형상 내부의 격자 설정은 원래 위치에도 유지
- `sections.boundaries`: 경계조건 및 계면 정의
- `sections.observations`: 관측 위치 · `outputs.probes` 포함
- 각 분류 안에서 기존 Config 키와 중첩 구조 유지 · 정의되지 않은 분류는 빈 객체
- 기존 요소 안에 물성과 형상이 함께 저장된 경우 전체 요소 보존
- Template에서도 필드 정의 대신 초기 형상 값을 표시 · 최종 저장 시 양식으로 변환
- 기존 최상위 공간 항목의 누락, 잘못된 분류, 자료형 오류는 저장 차단 · 요소 제거는 영역 목록에서 편집
- 공간 JSON에 포함되지 않은 물성·계산 조건·결과 저장 설정은 변경하지 않음
- 외부 형상 파일의 경로만 존재하는 경우 파일 내용은 이 JSON에 포함되지 않음

### 공간 JSON 예시

- 형식 설명용 예시 · 치수와 좌표는 사용자가 해석 대상에 맞게 입력
- 아래 예시는 Config 값 JSON · Template JSON에서는 해당 형상 항목의 필드 정의에 값을 보관

```json
{
  "geometry": {
    "fluid_regions": [
      {
        "name": "domain",
        "shape": "box",
        "unit": "m",
        "min": [0, 0, 0],
        "max": [4, 2, 3]
      }
    ]
  }
}
```


## 프로젝트에서 Template 생성

- 새 프로젝트의 CFD Template 선택란 옆 **+**: 기존 Template 생성 설문 열기
- 넓은 화면: 프로젝트 입력창을 왼쪽으로 이동하고 같은 높이의 Template 생성창을 오른쪽에 표시
- 좁은 화면: Template 생성창을 중앙에 표시
- 생성 중 프로젝트 입력은 보존 · 취소하면 기존 Template·프리셋·Config 유지
- 저장 성공 시 새 Template을 자동 선택하고 이전 Template의 프리셋·Config 선택 해제
- Template 저장과 프로젝트 저장은 별도 · 프로젝트 생성을 취소해도 저장한 Template은 유지
- 프로젝트 관리에서는 해석 Template을 변경할 수 없어 **+**를 표시하지 않음
- Viewer: 왼쪽 3D Virtual, 오른쪽 Data Sheet · 현재 모드의 테두리가 좌우로 이동
- 운영체제의 동작 줄이기 설정을 사용하는 경우 이동 애니메이션 비활성


## 솔버 추천 조건

- 설문 목적과 솔버의 전체 물리 모델을 분리해 판단
- 다상 유동에서 **유동**을 선택해도 지원되는 계면 추적 솔버 추천
- 다상 유체의 **열·부력 유동**은 지원되는 다상 열전달 양식과 연결
- 일반적인 유동 목적을 선택해도 다상 솔버에 필요한 상분율·계면 입력은 유지
- 온도 계산이 포함된 솔버를 선택하면 열물성·온도 입력도 유지
- 등록 양식과 조건이 다르면 후보별 변경 필요 항목과 변경 전·후 값을 표시
- **이 조건으로 다시 추천**을 누른 경우에만 응답 수정 · 수정 후 솔버 선택은 별도
- 정상 해석 + 물리시간 종료 등 등록 양식에서 지원하지 않는 조합은 자동으로 승인하지 않음
- **여기에 없음**은 지원 불가 유지 · 임의 대체 조건을 제시하지 않음
- 후보 추천은 등록 양식 지원 기준 · 설치·실행 연결·계산 검증은 별도

## 하드웨어 사용률

- CPU: Windows 시스템 시간의 차이로 계산한 전체 프로세서 활동 비율
- GPU: Windows GPU Engine 성능 카운터에서 프로세스별 사용률을 같은 엔진 단위로 합산한 뒤 가장 높은 엔진 사용률 표시
- NVIDIA 장치 UUID와 Windows LUID를 연결해 GPU별 값을 구분 · 카드 순서만으로 측정값을 배정하지 않음
- 작업 관리자와 같은 GPU 집계 원칙 사용 · 측정 구간과 갱신 시점 차이로 순간 표시값은 다를 수 있음
- VRAM: NVIDIA NVML의 사용량·전체 용량 · GPU 활동 비율과 별도
- C·D 등 드라이브: 저장공간 점유율 · 디스크 입출력 활동률과 다름
- 수집·화면 갱신: 약 1초 주기 · CFD·WSL 상태 조회와 독립
- 4초 이상 지난 값과 측정 실패는 현재 사용률로 표시하지 않음
- Windows GPU 엔진을 읽지 못하면 다른 기준의 NVIDIA 활동률로 대체하지 않고 **—** 표시
- 현재 GPU 측정 연결: NVIDIA Windows 드라이버·CUDA 장치 식별·Windows GPU Engine 카운터 필요 · 별도 CUDA Toolkit 설치 불필요
- 기준: [Microsoft GPU 집계 설명](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/), [NVIDIA 메모리 측정](https://docs.nvidia.com/deploy/nvml-api/index.html)


## Config 편집 및 정의 파일

- Template·프로젝트·Case는 공통 Config 편집기 사용
- Config·3D 형상·JSON은 각각 독립 블록 · Config 오른쪽에 큰 3D 형상 블록 상시 표시
- JSON은 맨 오른쪽에 표시 · 열기·닫기 시 Config와 3D 영역의 폭 유지 · 좁은 화면은 가로 스크롤로 접근
- 분류 및 네임태그 선택 시 Config 목록 스크롤 유지
- JSON 저장은 편집 초안 반영 · 최종 저장은 Case의 실행 저장 또는 상위 Template·프로젝트 저장
- 실행한 Case의 Config·형상·JSON은 변경 불가 · 새 Case 사본에서 편집
- 정의 파일은 소유 Template·프로젝트·Case 내부의 `Assets/Definitions/<Config SHA-256>`에 저장
- `config.json`: 전체 입력 · `geometry.json`: 형상 관련 입력 · `mesh.json`: 격자 설정
- `Sections`: 항목별 JSON · `manifest.json`: 항목과 파일의 대응 및 정의 버전
- 이 파일 묶음은 입력 정의이며 계산 격자·결과 데이터가 아님
- 완성된 파일 묶음 생성 후 저장 기록에 연결 · 기존 버전 덮어쓰기 방지 · 기존 파일 변조 발견 시 저장 중단
- 저장 실패 후 연결되지 않은 파일 묶음이 남을 수 있으며 기존 기록은 유지
- 외부 파일 경로는 자동 실행·복사하지 않음 · 기존 외부 참조 및 원본 보존
