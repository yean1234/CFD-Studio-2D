# 공급 시작부터 정상상태까지: 계산과 Studio 3D 재생

## 구현 범위

- 초기 농도 C=0, 흡착량 Q=0을 저장하고 공급 시작을 t=0으로 정의한다.
- 지정 자유 공기 영역에서 유한 시간 동안 정규화 생성항을 적용한다. 공급 종료가 계산 시간격자와 일치하지 않아도 시간 구간의 겹친 길이로 적분한다.
- 정상상태 또는 지정 시간 종료를 JSON의 termination으로 선택한다. 공급이 끝나기 전에는 정상상태로 종료하지 않는다.
- 기존 Studio의 프로젝트 목록, 3D 캔버스, 카메라, 배속, 시간 슬라이더, 영상 내보내기를 공유한다. C와 Q는 겹쳐 색을 혼동하지 않도록 하나씩 선택한다.
- 농도는 C/C_ref, 흡착량은 벌크 체적 기준 Q/C_ref다. Q는 다공성 영역 안에서만 존재한다. 기포나 공기 속 입자로 표현하지 않는다.
- 모든 저장 시점에 같은 색상 범위를 사용한다. 0인 평면을 삭제하지 않으며, 초기 0초에도 계산 영역·적재 영역·공급 영역을 표시한다.
- 재생 중 저장 프레임 사이에서는 같은 셀의 스칼라값을 시간 선형 보간한다. 추가 CFD 계산 결과가 아니라 표시 보간이다. 파일이 없거나 읽기에 실패하면 시간을 계속 흘리지 않는다.

**실제 PH3-쌀 저장고의 실험 검증은 아직 아니다.** 이 시험은 정지 공기의 정규화 수송이며, 실제 공급량·물성·선정 저장고의 치수로 해석한 결과가 아니다. 신규 생성과 계산 실행은 CLI, 완료 결과의 표시는 기존 Studio UI로 연결된다. 원래 액침냉각/저장고 실행기에 훈증 설정이 잘못 전달되지 않도록 서버에서 차단한다.

## 정상상태 판정

전 셀에 대해 아래 두 조건을 모두 확인한다.

```text
max(|C_new-C_old|)/dt <= absolute_rate_per_s + relative_rate_per_s * max(|C_new|)
max(|Q_new-Q_old|)/dt <= absolute_rate_per_s + relative_rate_per_s * max(|Q_new|)
```

추가로 공급 보정 총질량 상대 오차 <= 1e-8, minimum_time_s 경과, 공급 종료 조건을 만족해야 한다. 위 조건을 hold_s 동안 연속으로 만족해야 정상상태 종료한다. 판정값은 실행 전에 기록되며 재개 시 유지 시간을 다시 검증한다. 연속 공급되는 밀폐계는 질량이 계속 늘 수 있으므로 단순히 유속 U=0이라는 이유로 정상상태라고 처리하지 않는다.

현재 수치시험의 허용치는 상대 변화율 1e-4 /s, 절대 변화율 1e-8 /s, 최소 시각 4 s, 유지 2 s다. 이 값은 사용자가 변경할 수 있는 수치 종료 기준이지 논문에서 확인한 실험 기준이 아니다. `end_s`는 안전한 최대 길이다. 상한 도달은 `time_limit`, 정상상태 도달은 `steady`로 구분한다.

## 기록되는 시간

| 기록 | 의미 |
|---|---|
| NPZ times, Viewer t | 공급 시작 이후 물리적 모사 시간 (s) |
| dt_s | 방정식 계산 간격 |
| write_interval_s | 전체 3D 농도장 저장 간격 |
| saved_frames | 0초 및 마지막 정상상태 저장본을 포함한 개수 |
| elapsed_s | 격자 생성·검사·솔버·결과 분석에 걸린 벽시계 시간; Python 케이스 파일 생성은 제외 |
| solver_segment_wall_s | 해당 솔버 실행 구간의 경과 시간; 마지막 결과 기록 직전 진단 시점 |
| solver_segment_physical_s | 해당 솔버 실행 구간에서 진행한 물리적 시간; 재개 전 구간은 제외 |
| progress.csv | 각 계산 단계의 물리시간, 실행 구간별 벽시계 시간, C/Q 변화율, 수지 오차, 안정 유지 시간, 저장 프레임 수 |

계산 속도와 Viewer 재생 속도는 별개다. 저장 간격이 1 s여도 1배속 재생은 현실 1초에 모사 1초를 진행한다. 재개 로그의 벽시계 값은 구간마다 다시 0에서 시작하므로 합산이 필요한 경우 실행 구간을 구분해야 한다.

## 실제 시험 결과 (2026-09-24)

1,280셀, 영역 1 x 0.2 x 0.2 m, 내부 다공성 직육면체, 계산 간격 0.05 s, 저장 간격 1 s의 수치시험:

- 초기 C/Q 전 셀 0 확인. t=0~2 s에 정규화 생성항 적용.
- 정상상태 종료: 119.25 s. 프레임 121개 (0~119 s의 120개 + 마지막 119.25 s).
- 초기 시험 wall time 0.735 s, solver segment 0.535 s. 작은 검증 격자와 가정한 확산계수의 결과로, 실제 PH3 또는 대형 저장고 계산시간의 견적이 아니다.
- 공급 보정 질량 상대 오차 2.38e-11. 음수 C/Q 없음.
- 공급 중 1 s에서 중단·재개 후 연속 계산과 비교: 최대 차이 2.22e-16.
- 최대 6 s 제한에 걸린 정상상태 미도달 사례: 도달 실패로 판정.
- 격자 시각과 맞지 않는 0.123 s 펄스: 공급량 적분·질량수지 통과.
- 기존 9개 확산/다공성 기준선 재실행 통과.
- 독립 브라우저의 1배속 시험: 현실 3.0001 s 동안 물리시간 2.9994 s 진행.
- 1440 x 1000 및 390 x 844 화면 검사. 농도/흡착량 전환, 0초 초기장, WebGL 비어 있지 않음 확인. 사용 중인 Chrome 세션은 조작하지 않았다.

## 실행 및 표시

OpenFOAM 환경을 불러오고 저장소 루트에서 실행한다. 출력 폴더는 새 이름을 사용한다.

```bash
source /usr/lib/openfoam/openfoam2312/etc/bashrc
(cd tracer_transport/solver && wmake)
/tmp/cfd-tracer-env/bin/python -m tracer_transport.run \
  --config tracer_transport/supply_test.json --case porous --nx 20 --dt .05 \
  --output "$HOME/cfd_tracer_runs/supply_new"
/tmp/cfd-tracer-env/bin/python -m tracer_transport.export_studio \
  "$HOME/cfd_tracer_runs/supply_new/porous_20_0.05" \
  cfd_studio/Project/Tracer_Supply
```

Studio를 재시작한 뒤 Viewer에서 해당 프로젝트를 선택한다. 이미 실행 중인 구버전 Studio는 재시작 전까지 새 표시 코드를 읽지 않는다. 원본의 스칼라 `C`를 이전 시각화의 벡터 셀 좌표 `C`로 복사하지 않는다. 전용 CON1/SOR1 형식을 사용한다.

같은 결과를 다시 export하면 동일 프레임은 다시 쓰지 않는다. 다른 설정 또는 기존 프레임 값이 달라진 경우 별도 프로젝트가 필요하다. Viewer의 업데이트는 게시된 프레임을 다시 읽으며, 미게시 Raw 데이터의 자동 변환은 아니다.

프로덕션 솔버를 건드리지 않고 화면만 확인하려면:

```bash
python3 -m tracer_transport.preview cfd_studio/Project/Tracer_Supply --port 8728
```

이 서버는 실제 Studio HTML/JS와 결과 파일을 사용하되 실행·삭제 API는 차단하는 읽기 전용 검사 서버다. 실제 실행 서버의 WSL 연결 검증을 대체하지 않는다.
