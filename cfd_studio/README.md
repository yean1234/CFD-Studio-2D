# CFD Studio 사용법

> Git 배포 설치는 [루트 README](../README.md)를 먼저 확인하세요. 이 문서에는 개발 이력이 포함되어 있습니다. Git 배포본은 Python embedded 런타임을 포함하지만 별도 Python 설치 EXE, WSL 압축 도구, 기존 프로젝트 결과는 포함하지 않습니다.

**실행:** `실행.bat` 더블클릭 → 브라우저 자동 열림 · 로고 옆 **v174** 표기로 최신 버전 확인

---

## 가장 빠른 사용법 — 첫 계산 5단계

1. **설정 선택** — 왼쪽 위 토글 목록에서 사용할 설정을 고릅니다. 유량·입구 온도·Lee 계수·격자 같은 상세값을 바꾸려면 토글 오른쪽 **＋**로 새 설정을 만듭니다.
2. **＋ 새 프로젝트** — 버튼을 누르면 새 프로젝트 카드가 생깁니다. 시간·발열·냉각·형상 값은 설정 카드 오른쪽 **＋**에서 바꿉니다.
3. **출력 데이터 선택** — 기포 · 액체 상분율 · 유동 · 온도장 중 필요한 것만 고릅니다. 유동은 혼합 속도장 `U`의 유속 화살표로 표시합니다.
4. **실행** — 긴 파란 **[실행]** 버튼을 누릅니다. 실행 중에는 입력이 잠기며, CFD Studio 창은 켜 둡니다.
5. **결과 보기** — 상단 **[Viewer]** → 프로젝트 클릭 → **[생성]** → 하단 재생 버튼. 새 계산 결과를 기존 변환본에 더할 때만 **[업데이트]**를 누릅니다.

버튼 의미는 간단합니다: **실행**=0초부터 시작 · **실행 재개**=마지막 완전 저장 시점부터 계속 · **리셋**=설정은 유지하고 진행 자료만 Trash로 이동 · **중단**=현재 계산 정지.

## 1. 처음 한 번 — 새 컴퓨터 설치

| 순서 | 할 일 |
|:---:|---|
| 1 | `Setup\Python312` 확인 — 공식 **Python 3.12.10 x64 포터블 런타임**이 포함되어 별도 설치 불필요. `Python-3.12.10-x64.exe`는 수동 복구용 |
| 2 | `OpenFOAM_케이스` 폴더를 통째로 복사해 오기 |
| 3 | `cfd_studio\설치.bat` 더블클릭 — WSL·OpenFOAM·케이스·보조도구 자동 구성 후 **자체 검증까지 수행** (WSL이 처음 깔리면 재부팅 후 한 번 더) |
| 4 | `실행.bat` 더블클릭 — 끝 |

- 경로·포트가 다른 PC → `studio_config.json`만 수정 (`설치.bat`도 `wsl_case`를 읽어 해당 Linux 경로에 배치합니다)
- `wsl_distro`를 비우면 Windows의 기본 WSL 배포판을 사용하며, 여러 배포판이 있으면 사용할 이름만 지정합니다
- 실행 직후 콘솔에 **[점검]** 줄이 뜹니다 — WSL·OpenFOAM·케이스·mpirun·taskset 유무를 자동 확인해 빠진 것만 알려 줍니다
- PATH에 `wsl` 명령이 없어도 v52는 Windows `System32\wsl.exe`를 자동 탐지합니다
- v81 설치 브리지는 Windows 한글·공백 경로를 WSL 명령행에 직접 넣지 않고 UTF-8 표준입력으로 전달합니다. `디지털트윈\OpenFOAM_케이스` 같은 경로를 ASCII 폴더로 옮길 필요가 없습니다
- WSL 케이스 경로는 공백 없는 경로 사용
- `실행.bat`은 시스템 Python·Conda·Microsoft Store 별칭을 사용하지 않고 포함된 **정확히 3.12.10 x64**만 실행합니다. 다른 PC에서도 Python 버전 충돌이 없습니다

## 권장 성능

아래 기준은 범용 OpenFOAM 사양이 아니라 이 프로젝트의 기본 3 mm 격자 약 94만 셀과 고정밀 2 mm 격자 약 311만 셀을 기준으로 한 운용 권장치입니다.

| 등급 | CPU | 메모리 | 저장공간 | GPU·용도 |
|---|---:|---:|---:|---|
| **최소** | 4코어 / 8스레드 | 16 GB | SSD 여유 40 GB | GPU 선택 · 3 mm 단기 시험과 결과 확인 가능, 계산 시간은 매우 길 수 있음 |
| **권장** | 12코어 / 24스레드 | 32 GB | NVMe 여유 100 GB | 3 mm 표준 계산 · CUDA 지원 NVIDIA GPU, VRAM 8 GB 이상 권장 |
| **고성능** | 16코어 / 32스레드 이상 | 64 GB 이상 | NVMe 여유 250 GB | 2 mm 약 311만 셀·장시간 계산·다수 프로젝트 · NVIDIA VRAM 16 GB 이상 권장 |
| **Viewer 전용** | 4코어 | 8 GB | 프로젝트 크기만큼 | WebGL2 브라우저 · 이미 변환된 프로젝트 재생, 프레임이 많으면 RAM 16 GB 이상 권장 |

- 운영체제: **Windows 10/11 x64 + WSL2 Ubuntu**
- GPU는 필수가 아닙니다. 검증된 NVIDIA CUDA·AmgX·PETSc 환경이 없으면 CPU GAMG로 계산합니다
- GPU가 있어도 압력 `p_rgh`의 선형해석만 PETSc CUDA PCGAMG로 GPU를 사용하고 나머지 방정식은 CPU에서 계산합니다. 격자와 MPI 통신 비용에 따라 CPU와 비슷하거나 느릴 수 있으므로 짧은 동일 구간으로 비교합니다
- **GPU Only**는 OpenCFD `openfoam-ecse/feature-gpu`를 NVIDIA `nvc++ -stdpar=gpu`와 Umpire로 별도 빌드·검증한 PC에서만 활성화됩니다. 단일 GPU·MPI 1개만 사용하며 CPU 프로젝트를 이 모드로 바로 재개하지 않습니다
- CPU는 논리 프로세서 수를 감지해 기본 60%만 자동 배정합니다. 1~80% 범위에서 직접 바꿀 수 있지만 솔버와 시각화 변환을 함께 사용할 PC는 60%를 권장합니다
- 데이터 간격이 짧고 총 시간이 길수록 원본 용량이 크게 증가합니다. 하드웨어 카드의 **데이터 총용량 / SSD 여유 / 원본 보관 여유**로 현재 상태를 확인합니다
- 우측 상단 **⚙ 환경 설정**에서 CPU 상한·MPI 작업자·계산 GPU·Raw 데이터 위치를 PC별로 선택합니다. 다른 PC는 CPU 60%·MPI 자동·GPU 자동·Raw 사용 안 함이 기본이며 특정 드라이브 문자를 가정하지 않습니다

## 1-2. 설정 만들기 — 설정 카드 오른쪽 **＋**

`config.json`을 외부에서 직접 편집하지 않고, 값을 하나씩 채워 **새 설정**을 만듭니다. 내부 저장 형식은 config.json입니다.

- 현재 설정을 출발점으로 수조 · 층/초기온도 · 발열 · 코일 · 하단 액체 · 상단 액체 · 하단 증기 · 상변화 · 격자 · 시간을 채웁니다
- **하단 비전도 액체**와 **상단 액체**는 이름·기준 온도·밀도·비열·점성·열전도도·체적팽창계수를 각각 입력합니다. 기본값은 TMC-49와 DI수이며, 수정값은 새 계산의 OpenFOAM `thermophysicalProperties`에 직접 기록됩니다
- 상단 액체는 현재 3상 모델에서 기화하지 않는 액상입니다. 하단 액체의 기화점·잠열·분자량과 증기 비열·점성·열전도도는 별도 입력합니다
- 냉각 코일의 OpenFOAM 열경계에는 입구 온도와 UA/h가 적용됩니다. `flow_LPM`은 T6 출구온도 환산과 실행 기록용이며 유량장을 직접 푸는 입력은 아닙니다
- 저장 전에 생성기와 같은 규칙으로 검사합니다 — 증발 C > 0, 응축 C < 0, 초기 유전체 온도 < 기화점, 층 높이 범위
- **[＋ 새 프로젝트]** 편집 상태에서 생성한 설정은 새 프로젝트에 즉시 적용되며, **[실행]** 시 그 설정으로 계산합니다
- 기존 프로젝트를 선택한 상태에서 생성한 설정은 JSON 프리셋으로만 저장됩니다. 선택 프로젝트의 `case_config.json`·현재 화면·재개 설정은 바뀌지 않습니다
- 파일은 `cfd_studio\configs\<이름>.json` 에 남습니다
- `프리셋`과 config 선택은 **설정** 하나로 통합되었습니다. 목록에는 기본 설정과 사용자가 저장한 설정만 표시되며, 프로젝트 설정을 다시 불러오는 중복 항목은 없습니다
- 설정 선택창을 펼치면 스크롤 목록 안에 저장 설정별 작은 🗑가 표시됩니다. 해당 `configs\<이름>.json`만 삭제하고 프로젝트·계산 결과는 건드리지 않으며, 기본 설정은 삭제할 수 없습니다
- 메인 화면에서는 **출력 데이터**만 고릅니다. **＋ 새 설정**에서 총 계산 시간과 데이터 추출 간격을 정하고 나머지 물리·격자 조건을 입력합니다. 재시작용 전체 상태 저장은 프로그램이 내부에서 자동 관리하므로 설정 화면에 노출하지 않습니다

## 2. 화면 — 모드

| 모드 | 하는 일 |
|---|---|
| **[CFD]** | 계산 실행 + 실시간 감시 — 진행률 · 열전대 T1~T6 차트 · 증기량 차트 · **솔버 지표**(Courant·Δt·잔차·계산속도) · 시스템 사용량 · 솔버 로그 |
| **[시각화]** | 추출된 결과 3D 재생 — 오른쪽 정보 블럭 아래에서 레이어 선택 |

항상 **[CFD]로 시작**하고, 전환은 위쪽 버튼으로만 됩니다 (자동 전환 없음).

### 식량 저장고 설정

- 설정 카드 오른쪽 **＋**에서 해석 유형을 **액침냉각용 / 식량 저장고용**으로 선택합니다. 저장된 설정 목록에도 유형이 함께 표시됩니다.
- 식량 저장고도 일반 CFD 프로젝트입니다. **새 프로젝트 → 설정 선택 → 실행/재개/중단** 흐름과 프로젝트·Raw 저장 규칙은 액침냉각 프로젝트와 같습니다.
- 솔버는 `simpleFoam`과 `pimpleFoam`, 난류 모델은 `kEpsilon`·`realizableKE`·`RNGkEpsilon` 중에서 선택합니다.
- `simpleFoam` 저장고 결과의 숫자는 물리 초가 아닌 반복 번호입니다. 설정의 **총 재생 시간**에 첫 결과부터 마지막 결과를 균등 배치하며, Viewer는 재생 초를 주값으로 표시하고 원본 반복 번호는 괄호 안에 보존합니다. `1×`에서는 설정한 재생 시간과 실제 경과 시간이 일치합니다.
- 저장고 Viewer의 기본 조합은 **압력장 + 속도장·흐름 마커**입니다. 화살표와 이동 마커는 저장된 `U` 벡터의 방향·크기를 사용하며, 정상상태 결과에서 프레임 간 변화가 작아도 공기 흐름 방향을 연속적으로 확인할 수 있습니다. 압력장과 난류장은 동시에 겹치지 않으며 사용자가 고른 레이어 상태는 해석 유형별로 유지됩니다.
- 출력 선택만 설정 유형에 맞춰 바뀝니다. 액침냉각은 **증기/액체 상분율/유동/온도장**, 식량 저장고는 **압력/난류/유동**을 표시합니다.

## 3. CFD 계산 — [CFD] 탭

1. **설정** — 기본 config 또는 사용자가 저장한 config를 토글 목록에서 고릅니다. 저장 설정 행 안의 🗑는 그 설정 파일만 지웁니다. 토글 오른쪽 **＋**는 현재 설정을 복제해 형상·냉각·물성·상변화·격자·저장 상세값을 편집한 새 설정을 만듭니다. 현재 설정은 아래의 긴 표시 영역에서 확인합니다. 실행 중에는 선택·추가·삭제·환경 변경을 모두 차단합니다.
   - 유량·입구 온도·코일 h·UA·격자·시간·액체 높이는 **＋ 새 설정**에서 입력합니다
   - 실행 순간 현재 설정 전체와 출력 선택을 프로젝트 `case_config.json`으로 저장합니다
2. **출력 선택** — **[새 프로젝트]**를 누른 뒤 필요한 데이터를 1개 이상 고릅니다
   - **액침냉각 설정**: 기포 `alpha.vapour`, 액체 상분율 `alpha.water + alpha.vapour`, 유동 `U`, 온도장 `T`
   - **식량 저장고 설정**: 압력 `p`, 난류 `k + epsilon`, 유동 `U`
   - 선택값은 프로젝트 설정에 고정되어 결과 변환·표시에 사용됩니다. 솔버 재개에 필요한 Raw 전체 상태는 별도로 유지합니다
3. **버튼은 [실행]·[리셋]·[중단]** — **[실행]**: 새 프로젝트면 새 계산(확인창), 현재 프로젝트(미완)면 중단 지점부터 재개(설정 변경 없음), 보관 프로젝트에서는 누르면 안내창(재개 불가 이유 + 설정 복사해 새 프로젝트 제안). **[리셋]**: 선택 프로젝트에 진행 데이터가 있을 때만 표시되며, 0초 상태로 **초기화만** 합니다. 새 프로젝트의 실행 전 0% 상태에서는 표시되지 않습니다
4. **[중단 시 자동 이어서 실행]** 체크박스 — 상태 부가 문구 없이 한 줄 라벨로 표시하며 세부 설명은 마우스 툴팁에서 확인. 사용자가 **[중단]**을 누른 상태는 WSL 케이스에 기록되어 앱을 껐다 켜도 자동 재개하지 않고, **[실행 재개]**를 직접 눌렀을 때만 해제됩니다
5. 실행 중에는 입력이 잠기고 실제 적용 중인 값이 보임 · [중단]으로 정지
6. 검은 콘솔 창은 닫아도 계산은 계속됨 — 단, **스튜디오는 켜 둘 것** (모든 창을 닫으면 WSL이 꺼짐)

보조 버튼: **[현재 설정 보기]** = config·조건·프로브 한눈에 (Windows 폴더의 설정·도구는 [처음부터] 실행 시 WSL 케이스로 자동 반영)

**프로젝트 리스트** — 결과는 `cfd_studio\Project\<프로젝트 이름>\`에 자동 보관됩니다. 실행 ID는 `meta.json`의 `run_id`로 따로 유지하므로 폴더 이름을 바꿔도 재개·중단 추적은 안전합니다. 같은 이름이 있으면 `이름 (2)`로 구분합니다. 현재 프로젝트는 **주황 테두리**로 표시되고 진행도는 **실시간 솔버 시각 기준·소수점 둘째 자리**까지 갱신됩니다. 보관 프로젝트는 저장된 마지막 시각 기준입니다. **CFD 리스트**는 설정·실행 대상, **Viewer 리스트**는 재생 대상을 독립적으로 선택합니다. Viewer에서 다른 프로젝트를 열어도 CFD 탭의 설정·출력 선택·에너지 수지에는 현재 실행 프로젝트의 config와 이력만 표시됩니다. **이름 더블클릭**은 화면 이름과 실제 폴더명을 함께 바꿉니다.

v72부터 사용자가 선택한 프로젝트는 늦게 끝난 목록·상태 요청이 덮어쓰지 않습니다. 다른 프로젝트를 삭제해도 실행 전 프로젝트에 이전 프로젝트의 진행률·로그가 나타나지 않으며, 로그를 보여 주는 `tail` 프로세스를 실제 솔버로 오인하지 않습니다.

**프로젝트 삭제·복구** — 🗑를 누르면 폴더를 즉시 지우지 않고 `cfd_studio\Trash\`로 이동합니다. 30일 동안은 Trash 안의 해당 폴더를 `Project\`로 다시 옮기고 원래 프로젝트 이름으로 바꾸면 복구됩니다. 앱은 삭제 시각이 기록된 CFD Studio Trash 항목만 30일 후 영구 삭제하며, 마커가 없거나 손상된 폴더는 자동 삭제하지 않습니다.

**실행·리셋 상태** — 진행 자료가 없으면 긴 **[실행]** 하나만 표시됩니다. 진행 자료가 있으면 **[실행 재개] [리셋]**으로 바뀝니다. **[중단]은 솔버만 멈추고 파일 이동·삭제·시각화 변환을 하지 않습니다.** 리셋은 사용자가 버튼을 직접 눌렀을 때만 설정을 남긴 채 Windows 프로젝트 진행 자료와 현재 WSL 케이스 진행 자료를 각각 영문 `Trash`로 이동합니다. 이후 [실행]을 누르면 같은 프로젝트 설정으로 0초부터 시작합니다. 새 프로젝트를 실제 실행하면 이전 WSL 원본은 삭제하지 않고 `~/tmc49_full_tank/ProjectRuns/<실행 ID>/`로 이동 보관합니다. 새 프로젝트는 서버의 대기 카드가 확정되기 전 실행할 수 없고, 현재/과거 프로젝트의 재개 경로로 들어가지 않습니다.

**프로젝트 저장 계층** — 계산 중에는 고빈도 Raw만 옵션에서 선택한 `CFD Studio/Project/<프로젝트명>/Raw_Data`에 기록하고, 설정·이력·시각화 자료와 재개용 계산 상태는 작업 PC에 둡니다. 계산과 시각화 변환이 모두 끝나면 프로젝트 폴더 전체와 WSL 계산 상태를 같은 D 프로젝트 폴더로 검증 이관합니다. C의 작업본은 대상 파일의 크기 검증이 끝난 뒤에만 제거됩니다. CFD Studio는 로컬 `Project`와 선택 드라이브의 `Project`를 한 목록으로 읽으므로 재시작 후에도 D 보관 프로젝트를 바로 재생하고 Raw 폴더를 열 수 있습니다. D 보관 프로젝트는 결과 열람 전용이며 계산 재개 대상으로 사용하지 않습니다.

대용량 이관 후 WSL 내부 여유 공간과 C 드라이브 여유 공간은 즉시 같아지지 않을 수 있습니다. CFD Studio와 계산을 모두 멈춘 뒤 `Setup/WSL_공간회수.bat`을 실행하면 솔버 실행 여부를 확인하고, WSL을 정상 종료한 상태에서 동적 VHDX의 미사용 영역을 압축합니다. 실행 중인 계산이 있으면 정리 도구는 아무것도 변경하지 않고 중단됩니다.

리셋 직후 화면은 새 프로젝트처럼 출력 데이터를 다시 고를 수 있고 긴 **[실행]** 하나만 표시됩니다. 시작 직후 실패해 완전한 재개 스냅샷이 없는 프로젝트에서 [실행]을 누르면, 확인 후 실패 자료를 Trash에 보존하고 같은 프로젝트를 0초부터 실행합니다. 시작 중 실패로 새 프로젝트 대기 정보만 사라진 경우도 선택한 프로젝트 ID·설정으로 자동 복구해 동일한 0초 재시작 경로를 사용합니다. 유효한 저장 시점이 있는 정상 중단 프로젝트는 기존처럼 그 지점부터 재개합니다.

**화면 복원** — 앱을 다시 켜면 마지막 종료 전 화면(모드·선택 프로젝트·레이어·배속·카메라 시점)을 복원합니다. 단, 실행 중이거나 중단 지점이 있는 현재 프로젝트가 있으면 과거 저장 선택보다 현재 프로젝트를 우선합니다.

실행·재개 직전에는 현재 PC의 WSL CPU·MPI·OpenFOAM·GPU를 다시 점검합니다. PC마다 Open MPI가 물리 코어와 논리 스레드를 슬롯으로 해석하는 방식이 달라도, 감지된 작업자 수를 안전하게 실행하도록 슬롯 옵션을 자동 적용합니다.

**성능** — Windows/WSL의 논리 프로세서 수를 자동 감지해 기본 **60%**를 MPI 작업자와 솔버 taskset CPU 집합에 함께 배정합니다. 예를 들어 32스레드 PC는 19개 작업자를 사용합니다. 시각화 재조립은 나머지 논리 CPU 집합에서 `nice 15`·`ionice idle` 우선순위로 실행해 Windows와 장치 드라이버 응답을 먼저 보장합니다. 우측 상단 **⚙**에서 1~80%와 자동/수동 MPI 작업자 수를 바꿀 수 있으며 실행 중 솔버에는 손대지 않고 다음 시작·재개부터 적용합니다. 설치된 NVIDIA GPU가 여러 개면 자동 모드가 VRAM과 최대 클럭을 비교해 선택하고, 설정 창에서 GPU 번호를 직접 고를 수도 있습니다. GPU 설치는 NVIDIA WSL CUDA Toolkit + NVIDIA AmgX + PETSc 공식 release + OpenFOAM 공식 `external-solver`를 사용합니다. 설치가 검증된 PC에서는 **압력 `p_rgh`만 PETSc CG+AmgX(CUDA 행렬·벡터)**로 자동 전환하고 나머지 방정식은 CPU에 유지합니다. 설치가 불완전하면 계산을 시작하지 않으며, 미설치 PC는 CPU GAMG입니다. `cudaErrorIllegalAddress`·PETSc 76이 발생하면 원본을 보존하고 같은 GPU 자동 재시도를 차단한 뒤 CPU GAMG로 전환합니다. 하드웨어 카드는 **CPU 전체 / RAM 전체 / GPU 전체** 현재값과 저장공간을 표시합니다.

GPU Only는 위 혼합 모드와 별개입니다. OpenCFD 개발 브랜치의 전용 bashrc, `Nvidia-gpu` 빌드, `nvc++`, GPU용 `icoReactingMultiphaseInterFoam`, WSL GPU, 공식 `Test-std_execution`, Umpire managed pool 및 CFD Studio 3상 smoke test를 시작 전에 모두 확인합니다. 실패하면 CPU로 대체하지 않고 실행을 차단합니다. 현재 계산이 끝난 뒤 `CFD_STUDIO_ACCEPT_NVIDIA_EULA=YES JOBS=4 ./tools/install_gpu_only_openfoam.sh`로 PC의 GPU compute capability에 맞는 전용 런타임을 빌드할 수 있으며, 실행 중 솔버가 있으면 설치기는 즉시 중단합니다. 설치와 검증 기준은 `OpenFOAM_케이스\문서\CFD_GPU_Only_OpenCFD_v2606_적용.md`에 기록했습니다.

**원본 데이터 보관** — 옵션에서 선택한 Raw 루트를 프로젝트 생성 순간 `meta.json`에 고정하고, 선택 폴더 아래 `runs\<실행 ID>\times\<CFD 시각>\processorN`으로 완전히 분리합니다. Raw 원본만 선택 드라이브에 보관하며, 변환된 `C`·`bub_*`·`flow_*`·`therm_*`·`phase_*`와 설정·이력은 기존 `cfd_studio\Project\<프로젝트 이름>\`에 유지합니다. 활성 계산·격자·로그·`p_rgh` 포함 재개 앵커와 기록 중인 최신 프레임은 빠른 WSL/SSD에 유지합니다. 기록이 끝난 과거 고빈도 프레임은 모든 MPI 조각의 필드 구성·크기·SHA-256이 일치한 뒤에만 이동하고 원래 시간 폴더를 링크로 바꿉니다. Viewer의 **[생성]/[업데이트]**와 `reconstructPar`는 기존 경로 그대로 원본에 접근합니다. 폴더가 없거나 쓰기 불가·공간 부족이면 C/WSL 원본을 유지합니다. 다른 PC에서 Raw 루트를 다시 선택하면 같은 실행 ID/시각 구조를 찾아 끊어진 링크를 복구합니다.

Windows의 `wsl.exe`·PowerShell·`nvidia-smi.exe`는 PATH와 표준 설치 위치를 함께 탐색합니다. 특수 배포 환경에서는 `CFD_STUDIO_WSL_EXE`·`CFD_STUDIO_POWERSHELL`·`CFD_STUDIO_NVIDIA_SMI` 환경변수로 실행 파일을 지정할 수 있습니다.

## 4. 결과 보기 — [시각화] 탭

1. **[생성] / [업데이트]** — CFD 계산 중에도 생성·업데이트를 실행할 수 있습니다. 이 PC에서 기존 25분할 솔버는 CPU `0-18`, 시각화 변환은 마지막 2개 CPU `30-31`과 `nice 15`·`ionice idle`을 사용하며 CPU `19-29`는 Windows 응답 여유로 남깁니다. **[업데이트]는 선택한 네 레이어가 함께 완성된 마지막 공통 시각을 찾고 그 이후 Raw만 변환**하므로 이미 만든 과거 구간을 다시 읽지 않습니다. **[생성]**은 저장 결과를 화면에 준비하고 첫 프레임에서 멈춥니다. 실제 애니메이션은 하단 재생 버튼에서 시작합니다. 프로젝트마다 변환 상태·잠금·압축 격자 캐시가 분리되어 서로 다른 프로젝트의 생성·업데이트를 동시에 실행할 수 있습니다. 같은 프로젝트는 이미 로드한 프레임을 유지하고 새 시각만 시간순으로 추가하며, 완성 프레임마다 중간 결과를 화면에 반영합니다. Studio나 브라우저를 다시 열어도 실행 중인 프로젝트 변환을 자동 감시합니다. Raw가 외부 드라이브에 있어도 대상 시각 하나만 보이는 임시 케이스에서 재조립해 전체 링크 스캔을 피하고, 큰 재조립 필드는 WSL 내부에서 압축해 작은 최종 바이너리만 프로젝트 폴더로 전송합니다. 내부 압축에 실패하면 기존 Windows 압축 경로로 자동 복귀하며 실패·누락 프레임은 완료로 계산하지 않고 다음 업데이트에서 재시도합니다. 완성된 바이너리는 ETag 브라우저 캐시로 재사용하고, 로딩 중 변환이 끝나도 갱신을 버리지 않고 한 번 더 증분 로딩합니다. 첫 공통 시각의 미리보기를 우선 표시하고, 420시각을 넘으면 네 레이어에 같은 균등 표본 규칙을 적용합니다.
2. **[자동 동기화]** — 위 변환을 알아서 반복. 주기는 스냅샷이 생기는 속도를 실측해 스스로 조절 (체크박스에 마우스를 올리면 현재 주기 표시). 변환 뒤에도 processor 원본은 삭제하지 않습니다. 외부 원본 보관이 켜져 있으면 별도 검증 절차로 선택 폴더에 이동하고, 꺼져 있으면 WSL에 그대로 둡니다
3. **프로젝트 데이터** — 선택한 폴더의 `config.json` · `C` · 기포 · 액체 상분율 · 유동 · 온도를 자동 탐지해 ✓·개수로 표시합니다. 실행 시 고르지 않은 필드는 **선택 안 함**으로 표시하고, 선택했지만 파일이 없으면 **없음**으로 표시합니다

   - 유동: `flow_<시각>.bin`
   - 온도: `therm_<시각>.bin`

   - v77 새 실행은 선택한 필드만 **데이터 추출 간격**(`viz_interval_s`)의 같은 CFD 시각에 저장·추출합니다. 상분율을 고르면 `alpha.water`와 `alpha.vapour`가 함께 저장되고, 재개는 시작 시 선택을 그대로 유지합니다. 이미 추출된 구형 프로젝트의 거친 alpha 구간은 20단계 표시 보간을 유지하며, 보간은 새 CFD 결과를 만드는 것이 아닙니다
   - 현재 보관된 `Test_V5`는 이 변경 전 결과라 기포·유동·온도는 0.01초 간격 834개지만 상분율은 전체 상태 앵커에서 얻은 0.5초 간격 16개입니다. 과거 CFD 값을 새로 만들지 않고 화면 보간만 사용합니다
   - 기포는 TMC의 `vapour` 상입니다. 47°C 기준 밀도는 TMC 액체 약 1530, 물 약 996, TMC 증기 약 11.4 kg/m³입니다. 현재 상변화 쌍은 `liquid ↔ vapour`뿐이라 물은 기화하지 않으며, 가벼운 증기가 상승하고 응축된 무거운 TMC 액체가 물속에서 가라앉는 것은 정상입니다
   - 단일 혼합 속도장 `U`만으로 액체별 입자를 표현하면 상 정체성을 오해할 수 있어 흐름 추적점은 제거했습니다. 상별 침투 높이와 액체 이동은 액체 상분율, 전체 순환은 유속장으로 판단합니다
   - 솔버 로그의 약 1470 K 최고값은 CPU 열유속 **벽 경계값**입니다. 같은 8.0 s의 인접 내부 유체는 최고 321.62 K이고 저장 온도장 834개도 모두 330 K 미만입니다. 현재 유체 단독 모델에는 고체 전도·벽 비등 열전달이 없어 CPU 표면온도는 정량값으로 인용하면 안 됩니다
   - `PHS2` 점유 마스크로 보드·코일 등 유체 셀이 없는 10 mm 빈 칸을 제거합니다. 한 셀에 물과 TMC 액체가 같이 있으면 우세상 색 하나로 섞지 않고 두 액상을 각자의 색으로 표시해 소량 응축액도 가리지 않습니다
   - 유속장은 세 상이 공유하는 혼합 속도장 `U`이며 DI 수와 TMC-49의 상별 독립 속도는 아닙니다
   - 액체가 초기 계면 반대편으로 이동·혼합한 위치를 판단할 때는 **액체 상분율** 레이어를 기준으로 봅니다
8. **그래프** (레이어 패널 맨 아래) — 켜면 화면 **왼쪽 위에 카드로 표시**되고, 재생 시점이 흰 세로선으로 함께 움직입니다: 열전대 온도 / 기포 부피 / 기포 셀 수 / 층별 평균 온도 (유전체·물). 프로젝트를 클릭하거나 마지막 시각화 화면을 복원할 때 그 프로젝트의 열전대 이력을 자동으로 불러와 T1~T6 라벨·열전대 그래프에 같이 반영합니다. T5는 조건의 입구온도, T6은 조건에 유량이 있을 때만 코일 열수지로 계산하며 유량이 없으면 `—`로 표시합니다. 켠 것만 위에서부터 차례로 배치되고, 마지막 선택은 다음 실행에도 복원됩니다
9. **온도 히트맵** — 열화상 색(흑→보라→주황→백), 백=하단 액체 기화점(기본 47°C). 하단·상단 액체층 구분 없이 **하나의 눈금**을 써 층 간 온도를 그대로 비교합니다
10. **오류 안내** — 잘못된 입력값(예 응축 Lee C 양수)은 빨간 테두리+안내 토스트, 서로 다른 실행의 데이터를 섞으면(셀 수·격자 불일치, 형식 오류) 화면 위 빨간 배너에 원인과 조치가 표시됨

**솔버 지표 — 안정성·수렴·속도** (CPU 사용량 카드 바로 위)

| 지표 | 보는 법 |
|---|---|
| **Courant 수 (max)** | 시간 정확도·안정성 지표. `maxCo`(기본 0.5) 근처에서 오르내리면 정상, 계속 튀면 Δx·Δt 재검토 |
| **시간 간격 Δt (s)** | `자동 안정`에서 입력값은 상한이며 Courant 조건에 따라 실제 Δt가 더 작아집니다. `고정`은 입력 Δt를 유지하지만 Courant 초과 시 불안정해질 수 있습니다. 카드 상단에 최근 평균 Δt와 입력 상한 대비 실제 계산량을 표시합니다. |
| **압력 잔차 (초기)** | 수렴 상태. 로그 스케일이며 값이 계속 커지면 발산 신호 |
| **계산 속도 (물리 s / 실제 h)** | 실제 1시간에 계산되는 물리 시간. 완주 예상 시간과 함께 보면 됨 |

## 6. 자주 쓰는 값

## 7. 문제가 생기면

| 증상 | 조치 |
|---|---|
| 화면이 예전 그대로 | 실행.bat 다시 더블클릭 (이전 실행 자동 종료) → Ctrl+F5 · 로고 옆 버전 확인 |
| 이전 프로젝트에 새 실행 진행이 겹쳐 보임 | 앱 재시작 한 번이면 자동 복구 — 보관 데이터는 안전 (실행마다 고유 ID를 발급하도록 수정됨) |
| 실행.bat 실행 후 `t` `r` `'...` 같은 알 수 없는 명령 오류가 보임 | 실행.bat의 포트 점유/PID 판정이 깨진 상태였음. 최신 `실행.bat`으로 교체 후 다시 실행하면 해결됨 |
| `console_run.sh`에서 `syntax error near unexpected token ';'` | v51에서 실행·리셋 명령 연결의 중복 세미콜론 제거 |
| WSL 연결 안 됨 / 케이스 없음 | v52는 `wsl.exe`를 자동 탐지. 계속 실패하면 설치.bat 한 번 더 (재실행 안전) |
| 프로젝트를 잘못 삭제함 | 30일 안에 `cfd_studio\Trash\`의 해당 폴더를 `Project\`로 옮기고 접미사를 제거해 원래 이름으로 변경 |
| 솔버 로그에 노란 [연결 진단] | 표시된 진단 내용이 원인 — 캡처해서 공유 |
| 레이어가 회색(비활성) | 선택한 Project 폴더에 해당 데이터가 없음 → 프로젝트 데이터 카드에서 없음 항목 확인 |
| 외부 폴더가 목록에 없음 | `cfd_studio\Project\` 바로 아래에 단일 프로젝트 폴더로 넣고 5초 대기 · 폴더명에 `/` `\` 사용 불가 |
| 입력칸이 비어 있음 / 새 기능 안 보임 | 실행.bat 재실행 → [처음부터] 실행 (설정·도구 자동 반영) |
| 선택했던 config 파일이 없어짐 | 화면에 이미 로딩된 설정 전체를 실행 요청과 함께 보내므로 그대로 실행 가능. 앱을 다시 켠 뒤라면 **설정** 목록에서 저장 설정 또는 프로젝트 설정을 다시 선택 |
| 다른 경로·포트의 PC | `studio_config.json` 수정 (포트 변경 시 실행.bat도) |
