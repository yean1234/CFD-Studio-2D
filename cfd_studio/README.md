## 폴더 구성

- `실행.bat`: 프로그램 실행
- `설치.bat`: 최초 설치
- `internal`: 내부 코드·화면·설치 보조 파일
- `Setup`: 포함 Python 실행 환경
- `configs`: 기본 Config
- `Projects`: 기본 프로젝트 저장 위치
- `Studies`: 기존 실험 자료
- `_runtime`: 앱 상태·캐시
- `app.py`, `__init__.py`: 실행·모듈 연결 파일
- `studio_config.json`: 개인 환경 설정
- 내부 파일은 개별 실행하거나 삭제하지 않음

## 1. 설치

1. 저장소 전체를 다운로드하고 압축을 풉니다. `cfd_studio`, `tmc49_full_tank`, `silo_reproduction`의 상대 위치를 유지합니다.
2. Windows에서 WSL2 Ubuntu를 설치하고 재부팅 및 Linux 사용자 생성을 마칩니다. `설치.bat`이 WSL 설치를 대신하지 않습니다.
3. PowerShell에서 `wsl -l -v`로 배포판 이름을 확인합니다. 이름이 Ubuntu가 아니면 `studio_config.example.json`을 `studio_config.json`으로 복사하고 `wsl_distro`를 수정합니다.
4. `설치.bat`을 실행합니다. OpenCFD OpenFOAM v2312, Linux Python/NumPy, 새 계산 폴더를 준비합니다. sudo에는 Linux 사용자 비밀번호를 입력합니다.
5. 완료 후 `실행.bat`을 실행합니다. 브라우저가 열리지 않으면 콘솔에 표시된 주소로 접속합니다. 기본 주소는 `http://127.0.0.1:8712`이며 포트가 점유되면 달라질 수 있습니다.

- Windows Python 3.12.10 x64는 포함되어 있습니다. 별도 Python 설치 EXE와 WSL 디스크 정리 도구는 포함하지 않습니다.

- 설치 대상 `wsl_case`가 이미 존재하면 보호를 위해 중단합니다. 기존 폴더를 삭제하지 말고 기존 설치를 사용할지 새 경로에 설치할지 결정하세요. 실패 후 일부 생성된 폴더도 자동으로 덮어쓰지 않습니다.

## 2. 환경 설정과 새 프로젝트

- 오른쪽 위 환경 설정에서 CPU 비율, MPI 작업자 수, 계산 모드를 확인합니다. 첫 시험은 CPU Only와 자동 MPI를 사용하세요. CPU 60%는 작업자 배정 기준이지 전체 시스템 사용률을 항상 60% 이하로 유지하는 보장은 아닙니다.

- `＋ 새 프로젝트`를 누르고 설정 목록에서 `immersion` 또는 `grain_silo` 예제를 선택합니다. 설정 옆 `＋`에서 선택한 설정을 바탕으로 새 설정을 저장합니다. 예제는 시작점이며 실제 장치의 형상·물성·경계조건을 확인해야 합니다.

| 해석 | 주요 설정 | 시간의 의미 |
|---|---|---|
| 액침냉각 | 수조, 액체층, 발열체, 코일, 물성, 상변화, 격자, 저장 간격 | 비정상 해석의 물리시간 |
| 저장고 simpleFoam | 형상, 유입, 다공성 저항, 난류, 격자, 종료 조건 | 정상해석의 반복 번호 |
| 저장고 pimpleFoam | 위 조건과 시간간격·종료 시각 | 비정상 해석의 물리시간 |

- 저장고도 같은 프로젝트 체계를 사용합니다. 정상해석 Viewer의 재생 초는 반복 결과를 배치한 표시 시간이며 실제 공기의 경과 시간이 아닙니다.

- 새 설정은 `configs/<이름>.json`에 저장합니다. 기존 프로젝트를 선택한 상태에서 설정을 추가해도 기존 프로젝트의 실행 설정은 바뀌지 않습니다. 새 조건은 새 프로젝트에 적용하세요. 계산 중에는 설정 변경이 차단됩니다.

- 새 설정창을 열어 둔 동안 해석 유형을 바꿔도 유형별 입력을 유지합니다. 정상·비정상 솔버의 반복 횟수와 물리시간도 각각 보존합니다. 창을 닫고 다시 열거나 새로고침하면 미저장 초안은 보존되지 않습니다.

- 같은 이름의 설정은 덮어쓰지 않습니다. 이름이 겹치면 새 이름을 입력하세요. 저장 중에는 입력·닫기·중복 저장을 잠그며, 통신 실패 시 값을 유지하고 다시 편집할 수 있습니다. 빈 숫자 칸을 0으로 취급하거나 소수 격자 수를 정수로 반올림하지 않습니다.

- 액침냉각의 `전체 상태 저장 간격`은 재개에 필요한 전체 계산 상태의 저장 주기입니다. `데이터 추출 간격`은 시각화용 출력 주기입니다. 두 항목은 계산 시간간격과 별개이며, 선택한 설정의 값을 그대로 불러옵니다.

## 3. 실행·중단·재개

1. 필요한 출력 데이터를 선택합니다. 액침냉각은 증기·상분율·유동·온도, 저장고는 압력·난류·유동을 대상으로 합니다.
2. `실행`을 누릅니다. 격자 생성·분할 후 솔버가 시작하므로 처음에는 시간 표시가 증가하지 않을 수 있습니다.
3. 로그, 잔차, 시간간격, 저장 스냅샷, 디스크 여유를 함께 확인합니다. 짧은 첫 시험을 확인한 뒤 계산 규모를 확대하세요.
4. 멈출 때는 `중단`, 다시 계산할 때는 `실행 재개`를 사용합니다. 재개는 완전한 저장 상태가 있는 시점부터이므로 마지막 로그 시각과 다를 수 있습니다.

- `리셋`은 이어서 실행하는 버튼이 아닙니다. 진행 자료를 Trash로 옮기고 초기 상태로 되돌립니다. 재개 가능한 상태가 없다는 안내가 나오면 내용을 확인하고 결정하세요. 원본 폴더를 수동 삭제하여 해결하지 마세요.

- 계산 중 Studio 콘솔은 유지하는 것이 좋습니다. 브라우저와 솔버는 별도 프로세스이므로 브라우저를 닫았다고 계산 중단을 단정하지 마세요. 재부팅이나 WSL 종료 전에는 먼저 계산을 중단하세요.

## 4. 시각화

1. 시각화 화면에서 프로젝트를 선택합니다.
2. 변환 이력이 없으면 `생성`, 기존 결과에 새 Raw를 추가할 때는 `업데이트`를 누릅니다. 이미 변환한 결과를 재생하기 위해 매번 업데이트할 필요는 없습니다.
3. 완료 후 레이어와 재생 속도를 선택합니다. 마지막에 도달하면 재시작 버튼으로 처음부터 다시 볼 수 있습니다.
4. 스크린샷 버튼은 UI를 제외한 화면을 프로젝트의 스크린샷 폴더에 저장합니다. 화면에서 제공되는 영상·CSV 내보내기로 결과를 공유할 수 있습니다.

- 업데이트는 기존 변환본을 재사용하고 새 시점과 미완료 항목을 처리합니다. 솔버가 쓰는 중인 최신 데이터는 다음 업데이트로 보류될 수 있습니다. 부분 완료나 좌표 C 오류는 완료로 간주하지 말고 로그와 원본을 확인하세요. Raw에 없는 시점을 변환만으로 복원할 수는 없습니다.

- 온도·압력은 범례의 단위와 범위를 함께 읽으세요. 속도 화살표는 유동장 표현이며 물질 입자의 상변화 이력이 아닙니다. 정상해석의 움직이는 흐름 표현을 물리적인 시간 변화로 해석하지 마세요.

## 5. 데이터 위치와 보존

| 데이터 | 위치·역할 |
|---|---|
| 개인 환경 | `cfd_studio/studio_config.json`, Git 제외 |
| 사용자 설정 | `cfd_studio/configs/<이름>.json` |
| 프로젝트 | 사용자가 지정한 폴더. 기본값 `cfd_studio/Projects/<프로젝트명_ID>` |
| WSL 계산 상태 | `wsl_case`가 가리키는 Linux 폴더 |
| 원본·결과 | 프로젝트 생성·설정에서 지정한 폴더의 Case별 하위 폴더 |
| 삭제·리셋 자료 | 프로젝트 휴지통 또는 `_runtime/Trash`, 기본 보관 기간 30일 |

- 저장 폴더: 새 프로젝트 또는 프로젝트 설정에서 지정합니다. C·D 드라이브의 원하는 하위 폴더를 사용할 수 있습니다. 이전 결과는 원래 연결을 유지하고, 프로젝트 위치 변경 시 복사·검증합니다. 원본은 자동 삭제하지 않습니다.

- Windows 프로젝트 폴더만 백업했다고 모든 재개 자료를 보존한 것으로 판단하지 마세요. 수동 이동 전에는 계산·변환을 멈추고 WSL 상태까지 확인하세요. 외부 드라이브를 분리하면 해당 자료를 읽을 수 없습니다. WSL 내부 파일 정리 후에도 Windows의 가상 디스크 크기는 즉시 줄지 않을 수 있습니다.

## 6. 문제 해결

| 증상 | 확인할 내용 |
|---|---|
| WSL 연결 실패 | wsl -l -v, wsl_distro, Ubuntu 사용자 초기화 |
| 기존 케이스 감지로 설치 중단 | 보호 동작입니다. 기존 결과를 삭제하지 말고 설치 경로 확인 |
| Python 누락 | 저장소의 Setup/Python312 전체 복구 |
| 화면이 오래된 상태 | 계산·변환 상태 확인 후 앱 재시작과 브라우저 강력 새로고침 |
| 시각화 시점 부족 | 솔버 저장 시점, 선택 프로젝트, 변환 로그, Raw 드라이브 연결 |
| 계산 실패·발산 | 첫 오류 직전 로그, 입력값, 격자, 잔차 확인 |
| 공간 부족 | 계산 중단 후 Raw·WSL 디스크 위치 확인. 임의 삭제 금지 |
| GPU 시작 실패 | 별도 설치·검증 필요. 기본 설치만으로 GPU 동작을 보장하지 않음 |

- 문제 보고에는 버전, Windows/WSL 환경, 해석 종류, 재현 순서, 첫 오류 주변 로그를 포함하세요. 개인 경로·인증정보·비공개 협력 자료는 제거하세요.

## 7. 업데이트·공유

- 소스 업데이트 전에는 계산·변환을 멈추고 프로젝트와 환경 설정을 백업하세요. Git 업데이트와 WSL 케이스 재설치는 다른 작업입니다. 설치 배치를 업데이트 명령처럼 반복 실행하지 마세요.

- .gitignore는 결과·로그·개인 환경을 제외하지만 **사용자가 추가한 configs/*.json은 공유 가능한 소스로 취급됩니다.** 커밋 전에 비공개 장치 조건·물성 등이 없는지 확인하세요. 이미 추적하는 파일은 .gitignore로 자동 제외되지 않습니다.

- GPU Only는 개발 기능이며, 정확도와 속도는 해당 PC·케이스에서 확인해야 합니다. 웹 서버는 로컬 사용 전용으로 인터넷에 공개하지 마세요.
